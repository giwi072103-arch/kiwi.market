# Kiwi Market

Адаптивный маркетплейс цифровых товаров: React + TypeScript + Vite, Express, PostgreSQL. Светлая и тёмная темы, кабинет продавца, заказы и переписка, автовыдача, удержание средств, споры и админка.

## Запуск

```sh
npm ci
# Задайте переменные из .env.example средствами окружения.
npm run build
npm start
```

Для разработки без PostgreSQL можно использовать `LOCAL_DB=1 LOCAL_DB_PATH=.local-db npm start`. PGlite используется только локально и в тестах. В production обязательно подключение PostgreSQL через DATABASE_URL.

## Railway

Репозиторий: `giwi072103-arch/kiwi.market`, ветка `main`. Сборка через Dockerfile, здоровье: `/api/health`. Миграции применяются до запуска HTTP-сервера. База должна иметь постоянный volume.

Обязательные переменные:

- `DATABASE_URL`: ссылка `${{Postgres.DATABASE_URL}}`.
- `DATA_ENCRYPTION_KEY`: 32 случайных байта в hex, для AES-256-GCM. Не менять без миграции зашифрованных данных и не терять.
- `ADMIN_BOOTSTRAP_TOKEN`: независимый случайный секрет для однократного назначения владельца.
- `APP_URL`: точный HTTPS адрес сайта, без завершающего `/`.
- `TELEGRAM_BOT_TOKEN`: необязательно, включает проверку Telegram Mini App initData.

## Первый вход в админку

1. Зарегистрируйте свой аккаунт на сайте.
2. В профиле нажмите «Я владелец площадки».
3. Возьмите ADMIN_BOOTSTRAP_TOKEN из Variables сервиса / общих переменных Railway и введите его в форму.
4. После назначения владельца повторное назначение этим способом запрещено, даже с тем же кодом. Удалите bootstrap-переменную из Railway.

Публичных паролей и заранее созданного администратора нет. Права владельца не назначаются первому зарегистрированному пользователю автоматически.

## Роли

| Роль | Возможности |
|---|---|
| Пользователь | Покупки, собственные объявления, чат своего заказа, отзыв по завершённой покупке |
| Модератор | Модерация объявлений, просмотр пользователей и заказов, участие в переписке |
| Администратор | Дополнительно блокировки обычных пользователей, категории, комиссия, решение споров, журнал |
| Владелец | Дополнительно назначение ролей и ручные коррекции учёта с обязательным основанием |

## Деньги и автовыдача

Суммы — целые копейки, валюта учёта RUB. Оплата списывает баланс и создаёт удержание атомарно. Подтверждение покупателя зачисляет продавцу сумму за вычетом зафиксированной при покупке комиссии. Спор блокирует обычное подтверждение. Возврат возвращает покупателю удержанную сумму. Повторное завершение запрещено; повторный запрос покупки с тем же ключом возвращает существующий заказ.

Автовыдача расходует одну зашифрованную запись склада. Раскрытые данные не возвращаются на склад при возврате. Секрет видит только покупатель соответствующего заказа. Администрация видит статус и переписку, но не получает секреты товара через API заказа.

## Telegram

Установите TELEGRAM_BOT_TOKEN и укажите HTTPS URL сайта как Mini App / menu button у своего бота через BotFather. В Mini App вход выполняется по подписанным initData с проверкой возраста. Для одного аккаунта на сайте и в Telegram сначала войдите по почте внутри Mini App, затем нажмите «Привязать Telegram» в профиле. Уже созданный отдельный Telegram-аккаунт автоматически не объединяется.

## Ограничения раннего доступа

- Платёжный провайдер ещё не выбран: внешние пополнения и выплаты не реализованы и интерфейс не обещает их выполнение. Ручная коррекция баланса владельцем — учётная операция, не банковский перевод.
- Перед коммерческим запуском нужны реальные платёжные интеграции, правила площадки и возвратов, контакты поддержки и резервное копирование.
- Вход по почте пока без подтверждения адреса и восстановления пароля; не используйте его для коммерческого запуска до подключения почтового провайдера.
- Изображения задаются HTTPS-ссылкой; загрузка файлов не подключена.
- Чат обновляется кнопкой; push-уведомления и websocket не подключены.
- Каталог возвращает до 48 результатов на запрос, личные списки — 100, административные — 200 последних записей.
- Двухфакторная авторизация, автоматические выплаты и расширенная аналитика не реализованы.
- Товары и отзывы не подменяются демонстрационными данными: новая база открывается с пустым каталогом.

## Проверка

`npm run build` проверяет TypeScript и собирает интерфейс. `npm test` запускает интеграционные проверки на локальном PostgreSQL-совместимом PGlite: разграничение доступа, модерация, конкуренция за последний экземпляр, идемпотентность, спор, комиссия, возврат, запрет повторного отзыва, блокировка, CSRF, шифрование и подпись Telegram. Для высокой нагрузки нужны дополнительные конкурентные проверки на полноценном PostgreSQL.
